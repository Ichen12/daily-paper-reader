## 摘要
语音对话系统的最新进展要求文本到语音（TTS）模型更快、响应更迅速。现代语音对话系统对TTS模型提出两个主要要求：低延迟以及支持流式输入和输出。然而，现有的大多数基于单码本LLM的TTS方法依赖多阶段流水线，缺乏原生流式能力。这些系统通常因缓慢的自回归预测和多步流匹配而导致较高的端到端延迟。为解决这些局限，我们提出FlashTTS——一个开源的低延迟流式TTS框架。FlashTTS引入一种滞后多轨架构，可原生处理流式文本和语音输入，从而无需句子级缓冲。为加速声学生成，我们将并行多token预测（MTP）与X-pred均值流匹配解码器相结合。该配置在恰好两次函数评估（2-NFE）内实现高保真token到梅尔谱的生成。通过联合优化输入处理和解码效率，FlashTTS为实时语音对话系统提供了实用基础。实验表明，与强大的流式基线相比，FlashTTS将首包延迟大幅降至325毫秒，同时保持了强大的零样本声音克隆和跨语言可懂度。语音样本已提供。模型代码和检查点将作为开源发布。

## Abstract
Recent progress in speech dialogue systems requires Text-to-Speech (TTS) models to be faster and more responsive. Modern speech dialogue systems impose two primary requirements on TTS models: low latency and support for streaming inputs and outputs. However, most existing single-codebook LLM-based TTS methods rely on multi-stage pipelines that lack native streaming capabilities. These systems typically suffer from high end-to-end latency due to slow autoregressive prediction and multi-step flow matching. To address these limitations, we propose FlashTTS, an open-source and low-latency streaming TTS framework. FlashTTS introduces a lagged multi-track architecture that natively processes streaming text and speech inputs, thereby eliminating the need for sentence-level buffering. To accelerate acoustic generation, we integrate parallel Multi-Token Prediction (MTP) with an X-pred mean flow matching decoder. This configuration achieves high-fidelity token-to-mel generation in exactly two function evaluations (2-NFE). By jointly optimizing input processing and decoding efficiency, FlashTTS offers a practical foundation for real-time speech dialogue systems. Experiments show that FlashTTS substantially reduces First-Packet Latency to 325ms compared to robust streaming baselines, all while preserving strong zero-shot voice cloning and cross-lingual intelligibility. Speech samples are available. The model code and checkpoints will be released as open source.

## 研究背景与核心问题

- **核心问题**：现代语音对话系统要求 TTS 模型具备极低的端到端延迟并原生支持流式输入/输出。然而，当前主流的单码本大规模语言模型（LLM）TTS 方案通常依赖多阶段非流式流水线，自回归 token 预测速度慢，后接流匹配（flow matching）需多次函数评估（如 >10 步），导致整体延迟过高，难以满足实时交互的需求。
- **整体含义**：通过架构与训练策略的联合设计，实现一个开源、低延迟、高保真的流式 TTS 框架，为实时对话系统提供可部署的基础。

## 方法论

### 核心思想
- 消除句子级缓冲，实现逐 token 的流式文本输入处理。
- 用并行多 token 预测（MTP）打破自回归瓶颈，加速 token 生成。
- 用 X-pred 均值流蒸馏实现仅需 2 次函数评估（2‑NFE）的高效声学解码。

### 关键技术细节
- **滞后多轨流式架构**（图 1a）  
  将输入组织为并行的三个信息流：**语音轨、文本轨、语言轨**。语音轨以说话人嵌入开头后跟生成的语音 token；文本轨实时接收文本 token 并用填充 token 维持对齐；语言轨提供持续的语言条件。此组织方式使得模型无需等待完整句子即可开始合成。
  
- **并行多 token 预测（MTP）加速**（图 1b）  
  受 DeepSeek‑V3 启发，在冻结的主干 LLM（Qwen2‑0.5B）之上并行堆叠若干个轻量 MTP 模块（每个模块含线性投影 + Qwen2.5 解码器层）。各模块独立利用主干的最后一层隐藏状态 $h_{0:t}^0$ 生成未来 token 的预测：  
  $h_{0:t}^k = \text{MTP}_k(h_{0:t}^0),\quad k=1,\dots,N-1$  
  分布由共享输出头计算，用交叉熵损失监督：  
  $L_{\text{MTP}} = \sum_{k=1}^{N-1} L_{\text{CE}}(S_{0:T-k-1}^k,\, G_{k+1:T})$  
  推理时引入验证机制，用冻结主干的鲁棒概率分布校验并修正 MTP 预测量，保证音质。

- **X-pred 均值流蒸馏**  
  结合 Mean Flow 的理论框架与 JIT 的显式数据预测范式。  
  - 网络直接预测干净梅尔谱 $\hat{x}_\theta(z_t, r, t) = f_\theta(z_t, r, t)$，再从 $\hat{x}_\theta$ 解析出估计均值速度：  
    $\hat{u}_\theta(z_t, r, t) = \frac{1}{t}\left(z_t - \hat{x}_\theta(z_t, r, t)\right)$  
  - 目标 $u_{\text{tgt}}$ 由边际速度 $v_t = \epsilon - x$ 以及均值流恒等式导出：  
    $u_{\text{tgt}} = v_t - (t - r)(v_t \partial_z u_\theta + \partial_t u_\theta)$  
  - 损失函数：  
    $L_{\text{MF}}(\theta) = \mathbb{E}_{t, r, x, \epsilon} \|\hat{u}_\theta(z_t, r, t) - \text{sg}(u_{\text{tgt}})\|^2$  
  - 推理仅需 2 步函数评估（2‑NFE）：$z_0 = z_1 - \hat{u}_\theta(z_1, 0, 1)$，$z_1\sim\mathcal{N}(0,I)$。  
  - 同时引入块级注意力（block-wise attention）以支持流式梅尔谱生成。

### 训练流程
- **阶段一**：训练完整主干 LLM + X‑pred MeanFlow 解码器，优化声学生成通路。
- **阶段二**：冻结主干，仅训练 MTP 模块；同时从预训练的条件流匹配教师蒸馏 X‑pred MeanFlow 模型。

## 主要结论与发现

- **MTP‑3 (2‑NFE) 配置达到最佳实时平衡**：首包延迟 325 ms、RTF 0.632，相较于 CosyVoice2 大幅降低延迟且保持正向 CMOS。
- **多轨架构真正消除句子级缓冲**，FTL 降至 60 ms（CosyVoice2 需缓冲 5 个 token）。
- **X‑pred 均值流蒸馏使 2‑NFE 即可高保真合成**，3‑NFE 虽质量略升，但 2‑NFE 在延迟与质量间最优。
- **跨语言泛化良好**，在英、韩语上 WER 优于 CosyVoice2，并成功支持法、德语。
- **消融确认**：MTP 和 X‑pred 是加速的核心引擎，语言 ID 对跨语言稳定性至关重要。

## 优点

- **架构创新**：滞后多轨设计原生支持流式输入，避免句子级缓冲，大幅减少等待时间。
- **加速策略高效**：并行 MTP 突破自回归瓶颈；X‑pred 均值流将解码步数降至 2 步，协同实现极低延迟。
- **开源与可复现**：代码和模型将开源，并基于 0.5B 轻量参数，利于社区研究和部署。
- **实验设计严谨**：模拟真实对话场景测量延迟，多语言、多基线对比，消融分析清晰，主观评测规范。

## 不足与局限

- **说话人相似度有一定下降**：SIM 略低于部分重参数离线模型（如 Seed‑TTS），跨语言 SIM 更加明显。
- **语义‑声学建模的方差折中**：单码本 ASR 语义 token 虽利于预测，但可能丢失部分声学细节，影响风格复现的上限。
- **实验覆盖**：
  - 仅与 0.5B 量级的 CosyVoice2 进行详细延迟对比，未展现与更大 LLM 基线的速度权衡。
  - 未报告在实际全双工系统中端到端交互延迟或首句延迟等更贴近应用的指标。
  - 多语言数据集虽覆盖 6 种语言，但部分语言（法语、德语）WER 仍较高。
