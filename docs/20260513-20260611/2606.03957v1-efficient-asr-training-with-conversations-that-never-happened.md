## 摘要
低资源语言和利基领域的对话语音识别（ASR）受限于领域匹配的多说话人训练数据的稀缺性。我们提出了一种数据增强管线，该管线生成场景级对话并包含参与者元数据，将说话人属性映射到文本到语音（TTS）的声纹，并将合成的话语组装成具有说话人感知的模拟对话。我们使用相同的 FastConformer-Large 训练方案，在单生成器、固定预算混合和扩展设置下评估了五个大型语言模型（LLM）家族。我们在匈牙利语 BEA-Dialogue 基准语料库上进行了全面评估，该方法在具备各组件资源的情况下可应用于任何语言。结果表明，合成对话能持续提高语音识别性能，但生成器的选择和数据构成对提升效果影响显著。我们最大的训练配置仅使用了 67 小时的真实对话和 636 小时的模拟数据，在评估基准上比使用 2700 小时匈牙利语语音训练的零样本模型取得了更好的性能。这些发现表明，利用 TTS 合成的 LLM 生成对话数据是真实对话语料库的一种实用补充，可用于语音模型训练。

## Abstract
Conversational ASR for lower-resource languages and niche domains is limited by the scarcity of domain-matched multi-speaker training data. We propose an augmentation pipeline that generates scenario-level dialogues with participant metadata, maps speaker attributes to TTS voice profiles, and assembles synthesized utterances into speaker-aware simulated conversations. We evaluated five LLM families under single-generator, fixed-budget mixture, and scale-up settings using the same FastConformer-Large training recipe for each one. We ran comprehensive evaluations on the Hungarian BEA-Dialogue benchmark corpus, with the method itself being applicable to any language given the resources for each component. The results show that synthetic conversations consistently improve speech recognition performance, but generator choice and data composition strongly affect the gains. Our largest training configuration, using only 67 hours of real conversations and 636 hours of simulated data, achieves better performance on the evaluation benchmark than a zero-shot model trained on 2700 hours of Hungarian speech. These findings indicate that LLM-generated conversational data synthesized with TTS is a practical complement to real conversational corpora for speech model training.

### 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

-   **核心思想**：构建一个统一的、三阶段的增强管线，将 LLM 的文本生成能力、TTS 的语音合成能力与对话模拟的时序结构结合起来，从零开始创造出高质量、多样化、具有真实对话特征的合成训练数据。
-   **关键技术细节与流程**：
    -   **第一阶段：基于 LLM 的场景与对话生成**
        -   **场景生成**：使用一个提示词（Prompt），让 LLM 为每一个合成对话 $k$ 生成一个场景 $c_k$，包括话题 $t_k$ 和参与者元数据 $M_k$。每个参与者的元数据 $m_{k,j}$ 包含年龄 $a$、性别 $g$、职业 $o$ 和对话角色 $r$。
        -   **对话生成**：基于上一步生成的场景 $c_k$，再次通过 LLM 生成结构化的多轮对话 $U_k$，明确标注每句话的文本 $u_{k,t}$ 和对应的说话人编号 $z_{k,t}$。通过设置固定的示例对话，引导模型生成风格稳定、结构正确的输出，并进行格式和有效性过滤。
    -   **第二阶段：元数据条件的 TTS 合成**
        -   **声纹映射**：建立一个带有年龄和性别标注的 TTS 参考声纹库 $R$（来自真实语音片段，但与评估集无重叠）。
        -   **声纹选择**：对于场景 $k$ 中的每个说话人 $j$，根据其生成的性别 $g_{k,j}$ 和年龄 $a_{k,j}$，从库中选择性别匹配且年龄最接近的真实说话人声纹 $\rho^*_{k,j}$。公式为： $\rho^*_{k,j} = \arg \min_{r \in R: g(r)=g_{k,j}} |a(r) - a_{k,j}|$。
        -   **话语合成**：使用选定的声纹 $\rho^*_{k,z_{k,t}}$，通过 TTS 模型（xTTS-v2）将每句文本 $u_{k,t}$ 合成为语音片段 $\hat{x}_{k,t}$。
    -   **第三阶段：具有说话人感知的对话模拟**
        -   **时序构建**：将合成好的单句语音组装成一个完整的多说话人对话波形。这通过定义每句话的开始时间 $\tau_{k,t}$ 实现。
        -   **停顿与重叠建模**：起始时间递归算式为 $\tau_{k,t} = \tau_{k,t-1} + d_{k,t-1} + \Delta_{k,t}$。其中 $d_{k,t-1}$ 是上一句话的时长，$\Delta_{k,t}$ 是一个采样的句间偏移量。当同一说话人连续说话时，偏移量从分布 $P_{\text{same}}$ 采样；当说话人切换时，从分布 $P_{\text{switch}}$ 采样。该偏移量可为负（模拟重叠）或正（模拟停顿）。
        -   **最终输出**：将所有带时间戳的语音片段叠加，生成最终的混合对话音频 $\tilde{x}_k$ 及其对应的完整时间戳转写稿 $\tilde{y}_k$。

### 6. 论文的主要结论与发现

-   **合成对话总体有效**：使用 LLM 生成的合成对话进行数据增强，能一致且显著地提升匈牙利语对话 ASR 的性能，超越了所有仅用真实数据训练的基线。
-   **生成器选择至关重要**：不同 LLM 生成的数据对下游任务的增益差异显著。GPT 是最强的单生成器，而 Grok 和 Qwen 则效果较弱。仅凭生成数据的规模不足以解释性能差异，数据的语言学及声学特性同样关键。
-   **混合策略需谨慎**：在固定数据预算下，混合多个生成器并不总能带来提升。仅当混合具有互补性的强生成器（如 GPT + Haiku）时，才能取得轻微增益；加入弱生成器会稀释高质量样本，反而导致性能下降。
-   **扩展有效但有上限**：当移除预算限制并扩展合成数据量时，性能可进一步提升。结合多个强生成器的合成数据和基于真实话语的模拟对话，最终模型仅用 67 小时真实数据加 636 小时合成数据，在 cpWER 和 cpCER 上超越了在 **2700 小时真实语音**上训练的零样本模型。这证明了高质量合成数据可以作为稀缺真实数据的高效替代品。
-   **真实与合成数据互补**：混合基于 LLM 的合成对话和基于真实话语的模拟对话能带来最佳性能，表明两种方式捕捉了对话语音的不同互补维度。

### 8. 不足与局限：包括实验覆盖、偏差风险、应用限制等

-   **语言和领域单一**：实验仅在匈牙利语和 BEA-Dialogue 一个特定对话语料库上进行，未能验证该方法在其他语言、尤其资源更匮乏的语言或更复杂对话场景（如多人会议）下的通用性。
-   **依赖高质量外部资源**：管线效果高度依赖 LLM、TTS 和真实声纹库的质量。对于许多真正的低资源语言，可能无法获取到能够生成流畅文本的 LLM 或高质量的 TTS 系统，限制了方法的直接应用。
-   **模拟对话的逼真度限制**：对话模拟器基于统计分布的停顿和重叠，可能无法完美复现真实对话中复杂的交互、情感、韵律和话轮转换机制，与真正的自然对话依旧存在差距。
-   **合成数据质量的潜在风险**：LLM 可能生成模式化、有偏误或不自然的内容。尽管有过滤和示例提示，仍无法完全消除这种风险，过度使用可能使 ASR 模型学到不良的语言模式。
-   **成本与效率未全面评估**：虽然给出了 API 成本，但缺少对 TTS 合成时间和整体管线计算资源消耗（如总机时）的评估，难以全面衡量其相较于采集真实数据的成本效益比。
-   **生成器评估不全面**：对不同 LLM 的评估仅限于少数指令型 API 模型，且未探讨内部开源模型的表现，结论的普适性受到一定限制。
