## 摘要
我们提出了一个实时音乐界面，能将自然语言场景描述转化为不断演化的程序化声景。表演者输入诸如“午夜温暖爵士咖啡馆”的提示，并通过直接参数调整（如降低亮度、切换节奏风格）来操控它，每次调整都会产生可预测的声音变化，无需重新提示。与GPU驱动的文本转音频系统生成整体波形不同，我们的乐器在分类模式上生成人类可读的配置，从而实现对表演者的细粒度控制；大多数有效组合旨在实现音乐连贯性。三种可互换的后端——用于亚秒级纯CPU使用的嵌入检索、通过API托管的LLM以及微调的2.7亿参数本地模型——都输出相同的模式。实时生成器架构在后台解析新指令的同时持续输出音频，并在准备好时无缝交叉淡入淡出；即使LLM需要5-12秒响应，观众也能听到不间断的声音——将文本转音乐重塑为一种持续的、可表演的流，而非一次性生成。我们使用LAION-CLAP在保留的提示上评估文本-音频语义对齐作为技术代理，发现基于检索的配置在该指标上优于随机有效配置，同时注意到LAION-CLAP也指导了检索映射的构建。我们报告了性能观察、非正式听众反馈，并发布了SDK、数据集工件、模型和视听表演界面的材料。

## Abstract
We present a real-time musical interface that converts natural-language scene descriptions into evolving procedural soundscapes. A performer types a prompt such as "warm jazz cafe at midnight" and steers it through direct parameter adjustments - stepping brightness down, switching a rhythm style - each producing a predictable, audible shift without re-prompting. Where GPU-bound text-to-audio systems synthesize monolithic waveforms, our instrument generates human-readable configurations over a categorical schema, enabling fine-grained performer control; most valid combinations are designed to sound musically coherent. Three interchangeable backends - embedding retrieval for sub-second CPU-only use, hosted LLMs via API, and a fine-tuned 270M local model - all emit the same schema. A live generator architecture continuously emits audio while resolving new instructions in the background, crossfading seamlessly when ready; even when an LLM takes 5-12 seconds to respond, the audience hears uninterrupted sound - reframing text-to-music as an ongoing performable stream rather than a one-shot generation. We evaluate text-audio semantic alignment using LAION-CLAP on held-out prompts as a technical proxy, finding that retrieval-based configuration outperforms random valid configurations on this metric, while noting that LAION-CLAP also informed retrieval-map construction. We report performance observations, informal listener feedback, and release materials for the SDK, dataset artifacts, model, and audiovisual performance interface.

### 1. 论文的核心问题与整体含义（研究动机和背景）

*   **核心问题**：当前主流的文本转音频系统（如 MusicGen、Stable Audio）能生成高质量音频，但存在两大关键限制：
    1.  **缺乏实时操控性**：这些系统通常是“一次性”生成完整波形，用户无法对生成结果进行实时的、细粒度的参数调整（如“调暗一点”、“加快节奏”），必须重新生成或依赖不可预测的随机变化。
    2.  **高延迟/不可预测性**：即使针对实时演奏进行微调，GPU计算带来的延迟和输出不可控性仍是现场表演的巨大挑战。
*   **研究动机**：为了解决上述问题，论文旨在设计一种**以表演者为中心、可实时操控的程序化声景乐器**。它将文本控制从“一次性生成命令”转变为“持续不断的演奏流”，使表演者能像操控传统乐器一样，通过语言进行宏观场景切换和微观参数调整，同时保证音频的连续性与变化的可预测性。
*   **整体含义**：这项工作重新定义了文本到音乐在人机交互中的角色，将其从生成式AI的“黑盒”输出，转变为一种**可解析、可解释、可实时操控的“数字乐器”**。它强调了**即时性（Immediacy）**、**可控性（Controllability）** 和**连续性（Continuity）** 三个核心设计目标，弥补了现有系统在实时表演场景中的空白。

### 2. 论文提出的方法论：核心思想、关键技术细节

*   **核心思想**：不直接生成音频，而是生成**可读的结构化参数配置**。将自然语言输入映射到一个预定义的、音乐上连贯的分类参数模式（Schema）上，然后由确定性程序化合成引擎根据这些参数生成声音。这解耦了“创意控制”与“音频渲染”。
*   **关键技术细节**：
    1.  **分类配置模式（Categorical Schema）**：
        *   包含34个参数，分为5组：全局参数（8个）、配器层（6个）、空间/纹理（5个）、旋律生成（10个）、和声（5个）。
        *   **所有参数均使用人类可读的分类标签（如 `brightness: dark | medium | bright`）**，这确保了LLM能稳定生成有效配置，同时提供比连续浮点数（如 `0.73`）更直观的操控性。
        *   其中8个参数支持有序的**相对步进调整**（`Step(+1)`或`Step(-1)`），例如“调高亮度两档”，实现了非文本的精确控制。
        *   设计目标：任何有效的参数组合在音乐上都应是连贯的。
    2.  **实时生成器架构（Live Generator）**：
        *   这是一个**异步流式接口**，核心是**将指令解析与音频输出解耦**。
        *   **工作流程**：表演者通过一个Python生成器（Generator）异步产出指令（文本提示、参数更新等）。
        *   **后台解析**：当新指令到达时，系统在后台开始处理（调用LLM、检索数据库或应用参数更新），而**音频引擎则继续播放当前配置**。
        *   **无缝过渡**：当新配置准备好后，系统通过**交叉淡入淡出**（Crossfade）与当前音频无缝衔接，听众听不到任何中断。
    3.  **三种可互换的后端（Backends）**：
        *   **快速模式（Fast / Embedding Retrieval）**：默认后端。使用离线构建的检索映射图，将预先生成的LLM配置（约10,500个）用句子嵌入模型索引。运行时，直接检索与文本提示最相似的配置，实现**亚秒级**（约1秒）响应，无需GPU。
        *   **外部模式（External / Hosted LLM via API）**：将提示发送给第三方LLM（如Gemini Flash）进行处理。虽然延迟较高（5-8秒），但由于后台解析机制，音频播放不受影响。
        *   **本地模式（Local / Fine-tuned 270M Model）**：在设备上运行一个微调过的270M参数模型，作为实验性探索。

### 7. 优点

1.  **创新的架构设计**：**实时生成器**（Live Generator）架构是最大的亮点，它创造性地**将AI的高延迟从关键路径中移除**，解决了LLM应用于实时系统（如音乐表演）的核心障碍。
2.  **巧妙的映射设计**：**分类参数模式**（Categorical Schema）的设计非常精妙。它不仅让LLM生成结果稳定可靠，还为人类提供了直观、可预测的控制手段，在“AI黑箱”和“人类控制”之间取得了良好平衡。

4.  **开源的生态贡献**：完整地开源了SDK、数据集、模型和界面，为后续研究者和艺术家提供了宝贵的工具和共享知识库。

### 8. 不足与局限

1.  **音色范围受限**：系统在音色多样性上无法与端到端的神经音频生成模型相比。对于如“具体乐器的音色”（如“upright bass”）或特定风格的模仿（如“硬摇滚”），该系统表现不佳。
2.  **评估的偏差**：如前所述，使用**与构建检索映射相同的LAION-CLAP指标进行评估**，是该方法的主要证据弱点。缺乏足够的人类感知评价实验，其“音乐连贯性”和“语义对齐”的结论可能不够坚实。
3.  **LLM后端的可靠性**：API驱动的LLM后端存在响应延迟（5-12秒）和偶尔的架构生成失败（如Gemini Flash），虽然有后台机制保障，但仍增加了系统复杂性和不稳定因素。
4.  **应用场景局限**：系统偏向于制作氛围、持续性的声景，对于需要强节拍、精细编排、或具体音色变化的音乐风格可能力不从心。
5.  **听众反馈不具统计意义**：收集的5位听众反馈仅作为非正式的设计输入，不能作为科学证据来支持关于“听众体验”的广泛性结论。
