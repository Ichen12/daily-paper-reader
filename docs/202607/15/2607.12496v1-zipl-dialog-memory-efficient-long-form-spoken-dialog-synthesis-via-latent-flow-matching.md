## 摘要
零样本对话TTS受益于流匹配，但基于稠密梅尔频谱的分钟级生成导致严重的内存瓶颈，通常迫使使用不自然的块合成。我们提出ZipL-Dialog，将条件流匹配转移到4倍时间压缩（25 Hz）潜在空间。为了在压缩下保持声学保真度，我们采用确定性梅尔自编码器，并辅以梅尔域监督，优化ZipFormer的分层下采样方案。实验表明，与基线相比，ZipL-Dialog将最大峰值GPU内存减少11.22倍，推理速度提高2.23倍，显著降低了单次多分钟对话合成的内存占用，同时保持了感知自然度。

## Abstract
Zero-shot dialog TTS benefits from flow-matching, but minute-scale generation on dense mel-spectrograms causes severe memory bottlenecks, often forcing unnatural chunked synthesis. We propose ZipL-Dialog, which shifts conditional flow-matching into a 4x time-compressed (25 Hz) latent space. To preserve acoustic fidelity under compression, we employ a deterministic mel autoencoder with auxiliary mel-domain supervision and optimize the ZipFormer's hierarchical downsampling schedule. Experiments show that ZipL-Dialog reduces maximum peak GPU memory by 11.22x and accelerates inference by 2.23x over the baseline, substantially lowering the memory footprint of single-pass multi-minute dialog synthesis while maintaining perceptual naturalness.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：现有零样本对话文本到语音合成（TTS）中，基于流匹配（flow-matching）的方法（如ZipVoice-Dialog）在生成分钟级的长对话时，由于直接在密集的梅尔频谱（mel-spectrogram）上建模，导致严重的GPU内存瓶颈。这使得模型不得不采用不自然的块合成（chunked synthesis），削弱了长程对话建模能力。

- **整体含义**：本文旨在解决长对话TTS在非自回归（NAR）生成范式下的内存和效率问题，通过将生成过程迁移到时间压缩的潜在空间，实现单次（single-pass）多分钟对话合成，同时保持感知自然度。

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：将条件流匹配（Conditional Flow Matching, CFM）从帧级梅尔频谱域转移到4倍时间压缩的潜在空间（25 Hz），从而大幅缩短流模型处理的序列长度，降低内存和计算开销。

- **关键技术细节**：
  - **确定性梅尔自编码器（Deterministic Mel Autoencoder）**：采用确定性的瓶颈设计，而非变分自编码器（VAE）。通过一个编码器将100 Hz的梅尔频谱压缩为25 Hz的潜在序列（压缩因子r=4，潜在维度D=100），解码器恢复为梅尔频谱。训练时使用辅助的梅尔域重建损失（式5），以增强保真度。
  - **掩码潜在条件流匹配（Masked Latent Conditional Flow Matching）**：训练时对潜在序列的对话目标区域添加掩码，只对掩码区域进行线性插值路径的噪声添加，并通过速度匹配损失（式3）进行优化；同时将预测的潜在编码解码为梅尔频谱，计算辅助重建损失（式5），总损失为两者加权和（λ=0.5）。推理时，以观察到的前缀作为条件，从高斯噪声开始通过ODE积分生成目标潜在序列。
  - **ZipFormer下采样调度优化**：针对压缩后的潜在序列，重新设计ZipFormer的分层下采样比例。默认的密集帧级调度（[1,2,4,2,1]）在4倍压缩后过于激进，导致短音素分辨率下降。提出的优化调度为[1,1,2,1,1]，在局部分辨率、感受野和效率之间取得更好平衡。
