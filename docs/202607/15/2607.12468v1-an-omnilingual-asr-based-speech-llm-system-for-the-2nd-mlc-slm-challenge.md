## 摘要
我们描述了第二届MLC-SLM挑战赛任务1的参赛系统：一个级联的说话人日志-识别系统，结合了DiariZen-Large-s80 (WavLM-Large) 分割、基于CAM++嵌入的双说话人聚类，以及LoRA适配的omniASR LLM 7B v2识别器，测试时不使用oracle分割或说话人标签。在官方开发集（150段对话，21种语言/口音类别）上，系统达到了29.27%的宏平均tcpMER，而官方基线为79.15%；在评估集上得分为50.23%。我们还分析了两个显著影响tcpMER的工程选择。首先，基于嵌入的说话人聚类优于仅从ASR <sc> 轮次标记分配说话人的端到端式替代方案。其次，重叠感知分割虽然旨在提高说话人日志的召回率，但会增加tcpMER，因为重叠语音被转录了两次。

## Abstract
We describe our submission to Task 1 of the 2nd MLCSLM Challenge: a cascaded diarization-then-recognition system that combines DiariZen-Large-s80 (WavLM-Large) segmentation, CAM++ embedding-based two-speaker clustering, and a LoRA-adapted omniASR LLM 7B v2 recognizer, with no oracle segmentation or speaker labels at test time. On the official Development set (150 conversations, 21 language/accent categories) the system attains a macro tcpMER of 29.27%, versus 79.15% for the official baseline; on the Evaluation set it scores 50.23%. We also analyze two engineering choices that substantially affect tcpMER. First, embedding-based speaker clustering outperforms an end-to-end-style alternative that assigns speakers from ASR <sc> turn markers alone. Second, overlap-aware segmentation, although intended to raise diarization recall, increases tcpMER because overlapped speech is transcribed twice.

## 1. 论文的核心问题与整体含义（研究动机和背景）
- **研究动机**：多语言、多口音的真实对话场景中，自动语音识别（ASR）和说话人日志（Speaker Diarization, SD）联合任务仍然具有挑战性。第二届多语言对话语音语言模型挑战赛（MLC-SLM Challenge）的任务1要求系统在没有 oracle 分割或说话人标签的情况下，同时对原始录音进行说话人日志（谁在何时说话）和识别（说了什么），并使用时间约束最小排列错误率（tcpMER）作为唯一排名指标。
- **核心问题**：如何构建一个无 oracle 信息、能在 21 种语言/口音类别上有效工作的级联系统，使 tcpMER 大幅低于官方基线。
- **整体含义**：本文提出的级联管道（说话人日志前端 + 嵌入聚类 + LoRA 微调的多语言 ASR）在开发集上将 tcpMER 从官方基线的 79.15% 降至 29.27%（相对降低约 63%），证明了独立嵌入聚类和强分割模型的重要性。

## 2. 论文提出的方法论
- **核心思想**：采用**级联（cascaded）架构**，将说话人日志与识别解耦为四个独立阶段，便于单独替换和消融。
- **关键技术细节**：
  1. **语音活动检测（VAD）**：使用 FunASR 的 FSMN VAD（ModelScope checkpoint `speech_fsmn_vad_zh-cn-16k-common-pytorch`），作为所有配置的共享模块。
  2. **分割（Segmentation）**：对比两种神经网络分割器：
     - `pyannote/segmentation-3.0`（PyanNet powerset 模型，SincNet + BiLSTM，10s 窗口，10% hop）。
     - `BUT-FIT/diarizen-wavlm-large-s80-md`（DiariZen-Large-s80，基于 WavLM-Large + Conformer EEND，12s 窗口，10% hop）。最终提交采用后者。
   - 后处理：丢弃 <0.7s 片段，合并 ≤1.5s 间隙的同说话人片段，分割 >25s 片段。
  3. **说话人嵌入与聚类**：
     - 使用预训练的 **CAM++** 模型（`campplus_cn_en_common`），提取 192 维嵌入（子窗口 1.5s，步长 0.75s）。
     - 通过**谱聚类（spectral clustering）** 将所有子窗口嵌入聚成 2 个说话人，强制匹配双人电话对话。然后合并相邻同说话人片段，解决交叉重叠（较短片段让出重叠区域）。
  4. **多语言 ASR 与 LoRA 适配**：
     - 使用 Meta 的 **omniASR LLM 7B v2**（wav2vec2 编码器 + CTC 头），基于 LoRA 微调（rank=8, α=16, dropout=0.05），仅更新低秩适配器，冻结声学编码器。
     - 训练数据：挑战官方训练集（oracle 边界仅训练时可用），过滤 2–15s 长度的话语，打包连续参考分割轮次，在相邻不同说话人之间插入 `<sc>` 标记。
     - 训练超参数：CTC 目标，fairseq2 框架，FSDP + bfloat16，50k 步，AdamW（lr=2e-4, β=(0.9,0.98) 无 weight decay），三阶段学习率调度（warmup/hold/decay 比例 0.1/0.4/0.5）。
  5. **后处理**：
     - **说话人变化分割**：在识别输出中根据 `<sc>` 标记将长段拆分为子句，并按字符长度比例分配时间戳。
     - **重复假设去重**：删除近乎重复的子句（相同、子串、或序列相似度 ≥0.9）。

## 3. 实验设计
- **数据集**：
  - **开发集（Development set）**：150 段长对话（约 30 分钟电话信道），覆盖 21 个语言/口音类别（英语按口音分为 5 类，日语、韩语、泰语用 tcpCER 计量，其余用 tcpWER）。
  - **评估集（Evaluation set）**：官方未公开细节，包含 20,914 个片段，评估集得分 50.23%。
- **基准（Benchmark）**：官方任务 1 基线——LoRA 微调的 VibeVoice-ASR（微软开源），开发集宏平均 tcpMER = 79.15%。
- **对比方法**：
  - **Exp1**：端到端式基线——仅 VAD + ASR，通过 `<sc>` 轮次标记交替分配说话人（无单独分割/聚类），tcpMER = 141.2%。
  - **Exp2**：级联接入 `pyannote/segmentation-3.0` + CAM++ 聚类，tcpMER = 35.3%。
  - **Exp3**：在 Exp2 基础上禁用重叠感知分割，tcpMER = 30.6%。
  - **Exp4**：将分割器替换为 DiariZen-Large-s80，tcpMER = 29.27%（提交配置）。

## 6. 论文的主要结论与发现
1. **嵌入聚类显著优于轮次标记分配**：Exp1（仅 `＜sc＞` 分配）tcpMER 高达 141.2%，而加入 CAM++ 聚类后（Exp2）降至 35.3%，说明仅靠 ASR 输出的说话人变化标记**无法**可靠推断说话人身份。
2. **重叠感知分割损害 tcpMER**：虽然重叠检测理论上能提高日志召回率，但导致重叠区域被转录两次，在时间约束指标下产生更多插入错误。禁用重叠后（Exp3 vs Exp2）tcpMER 从 35.3% 降至 30.6%。
3. **DiariZen-Large-s80 分割优于 pyannote**：替换分割器后（Exp4 vs Exp3）再降低 1.3 个百分点，达到 29.27%。
4. **开发集与评估集存在较大差距**：评估集 tcpMER 为 50.23%，远高于开发集的 29.27%。推断主要原因是域偏移（speaker、信道、语言分布差异），尤其对困难类别（土耳其语、加拿大法语）影响明显。
5. **组件选择应直接以 tcpMER 为目标优化**，而非追求传统日志召回率等间接指标。
