## 摘要
神经音频编解码器（NAC）在获取语音表示作为离散标记方面变得流行。除了压缩，离散标记可用于训练自监督学习（SSL）模型。这类模型称为基于编解码器的SSL模型，减少了数据存储和计算成本，使得可扩展的SSL预训练成为可能。然而，它们的语言敏感性仍不清楚。当语言变化时，基于编解码器的SSL模型可能需要重新训练，这削弱了它们的效率。在本文中，我们通过固定其中一个而改变NAC训练语言或SSL预训练语言，对语言敏感性进行了系统分析。实验结果表明，下游性能对NAC训练语言不敏感，但强烈依赖于SSL预训练语言。这些发现表明，单个NAC可以跨语言重用，而将SSL预训练语言与目标语言对齐至关重要。

## Abstract
Neural audio codecs (NACs) have become popular for obtaining speech representations as discrete tokens. Beyond compression, discrete tokens can be used to train self-supervised learning (SSL) models. Such models, referred to as codec-based SSL models, reduce data storage and computational cost, enabling scalable SSL pre-training. However, their language sensitivity remains unclear. When the language changes, codec-based SSL models may require retraining, which undermines their efficiency. In this paper, we present a systematic analysis of language sensitivity by varying either the NAC training language or the SSL pre-training language while keeping the other fixed. Experimental results show that downstream performance is insensitive to the NAC training language but strongly dependent on the SSL pre-training language. These findings suggest that a single NAC can be reused across languages, while aligning the SSL pre-training language with the target language is crucial.

## 1. 论文的核心问题与整体含义

**研究背景：**

- 自监督学习（SSL）在语音任务（如自动语音识别 ASR、语音情感识别 SER）中被广泛用于构建通用特征提取器。
- 传统 SSL 预训练需要海量无标注语音数据和长时间训练，存储和计算成本高昂，限制了其可扩展性。
- 神经音频编解码器（NAC）可将语音波形压缩为离散 token，且这些离散 token 保留了丰富的声学和语言信息，可直接用于训练 SSL 模型（即**基于编解码器的 SSL**），大幅降低存储和计算成本。

**核心问题：**

- 基于编解码器的 SSL 模型对**训练语言**的敏感性尚不明确。
- 语言敏感性可能同时来自两个阶段：**NAC 离散化器**和**SSL 预训练阶段**，两者的贡献可能相互混淆。
- 如果语言变化时需要重新训练 NAC，将削弱其成本优势；如果只需调整 SSL 预训练语言，则可复用单一 NAC。

**整体含义：**

- 该研究旨在解耦 NAC 和 SSL 预训练两个阶段的语言敏感性，回答"语言变化时是否需要重新训练 NAC"这一具有直接实践意义的问题。

## 2. 论文提出的方法论

**核心思想：**

- 采用**控制变量法**设计实验，交替固定 NAC 训练语言或 SSL 预训练语言，系统地隔离两个阶段对语言敏感性的独立贡献。
- 通过三个递进的研究问题（RQ1–RQ3）逐步拆解语言敏感性的来源。

**三个研究问题：**

- **RQ1**：NAC 训练语言如何影响重建波形上的下游任务性能？（评估语音重建路径）
- **RQ2**：在基于编解码器的 SSL 中，SSL 预训练语言如何影响下游任务性能？（固定 NAC，改变 SSL 语言）
- **RQ3**：当 SSL 预训练语言固定为与下游语言匹配时，NAC 训练语言如何影响下游性能？（固定 SSL 语言，改变 NAC 训练语言）

**关键技术细节：**

- **数据集构建**：NAC 训练使用四种语言条件——EN+（英语）、JP（日语）、ZH（中文）、All（多语言），每个条件均采样 1056 小时数据以保证公平比较。
- **SSL 预训练**：采用 HuBERT 架构，使用冻结的 NAC 量化器，复用其预训练码本嵌入并求和作为 Transformer 输入（遵循 Codec2Vec 设计）。训练目标与标准 HuBERT 一致（掩码预测）。
- **伪标签生成**：
  - RQ2 采用 MFCC 两阶段聚类（标准 HuBERT 流程）；
  - RQ3 使用语言特定的 HuBERT Base 第 9 层特征进行 k-means 聚类生成伪标签。
- **语言敏感性度量**：使用**变异系数（CoV）**作为尺度无关的指标，将各语言的错误率相对波形输入基线归一化后计算跨语言变异程度，公式为：

    r_l = (1/|D_l|) Σ (ER_d / ER̂_d)，CoV = √(Σ(r_l − r̄)² / |L|) / r̄

  其中 ER_d 为数据集 d 的错误率，ER̂_d 为波形基线错误率。

## 6. 论文的主要结论与发现

1. **RQ1 结论**：NAC 训练语言对重建波形上的下游任务性能影响有限，DAC 是评估的 5 种 NAC 中跨语言最稳定的模型。NAC 训练语言不是跨语言下游性能变异的主要因素。
2. **RQ2 结论**：即使在 NAC 离散化之后，语言敏感性仍然存在；SSL 预训练语言与下游语言对齐时性能最佳（仅有少数例外）。语言特定信息在离散化后仍保留，下游相关结构主要在 SSL 预训练阶段获取。
3. **RQ3 结论**：当 SSL 预训练语言固定为与下游语言匹配时，NAC 训练语言的变化对下游性能影响很小，且使用与下游语言相同的 DAC 并不必然带来提升。**无需为每种目标语言重新训练声学 NAC**。
4. **总体结论**：基于编解码器的 SSL 中，语言特定特征主要在 SSL 预训练阶段获得，而 NAC 主要提供一种对语言不太敏感的表示。实践中应**跨语言复用单一声学 NAC**，同时**使 SSL 预训练语言与目标语言匹配**。

## 7. 优点

- **研究问题明确**：首次系统性地解耦了基于编解码器的 SSL 中 NAC 和 SSL 两个阶段的语言敏感性，填补了该领域研究空白。
- **实验设计精巧**：RQ1→RQ2→RQ3 层层递进，从重建波形到 token 输入的 SSL，逐步隔离变量，逻辑清晰。
