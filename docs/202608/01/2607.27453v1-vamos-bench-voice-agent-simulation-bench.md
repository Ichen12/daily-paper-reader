## 摘要
生产环境的语音智能体涵盖级联式、语音到语音式以及混合架构。语音智能体基准通常衡量组件质量和对话属性，如词错误率、延迟、自然度和轮流说话。较少有基准衡量智能体是否独立正确处理了电话呼叫。联络中心将此称为“包含率”（containment）：即自动化系统无需转接人工即可解决的电话呼叫占比。在某些电话呼叫中，正确的结果是拒绝或重定向。为弥补这一空白，我们推出了VAmoS Bench，即语音智能体模拟基准。它在一个有状态的客户支持任务中端到端地评估完整的语音智能体系统。该智能体名为Riley，是一家虚构银行的信用卡支持代表，能够冻结、取消、更换或激活卡片。100个场景中的每一个都提供一个具有私有目标的模拟呼叫者，并配有一个预置的PostgreSQL后端。该平台使用每个场景来填充并激活一个隔离模拟，呼叫者通过音频与Riley联系；约三分之一的场景施加对抗性压力。智能体可以使用五个工具，这些工具对后端执行真实的SQL。每个场景还定义了二元断言。评分器根据呼叫者和智能体所说内容的完整轨迹以及智能体所采取的行动（包括工具调用、参数和返回行）来评估这些断言。这可以捕捉到那些声称已更改卡片但未更新数据库的智能体，以及那些做出正确数据库更改却泄露受保护信息的智能体。该基准的首个版本聚焦于金融服务。其评估协议支持一个不断发展的排行榜：其他语音智能体可以在同一版本上被评估，而后续版本可以扩展任务和场景。

## Abstract
Production voice agents span cascaded, speech-to-speech, and hybrid architectures. Voice-agent benchmarks typically measure component quality and conversational properties such as word error rate, latency, naturalness, and turn-taking. Fewer measure whether the agent handled a phone call correctly on its own. Contact centers refer to this as ``containment'': the share of phone calls the automated system resolves without handing off to a human. On some phone calls the right outcome is refusal or a redirect. To address this gap, we introduce VAmoS Bench, the Voice Agent Simulation Bench. It measures complete voice-agent systems end to end in a stateful customer-support task. The agent is Riley, a credit-card support representative for a fictional bank who can freeze, cancel, replace, or activate a card. Each of 100 scenarios supplies a simulated caller with a private goal and a seeded PostgreSQL backend. The platform uses each scenario to populate and activate an isolated simulation in which the caller reaches Riley over audio; roughly one-third apply adversarial pressure. The agent can use five tools that execute real SQL against the backend. Each scenario also defines binary assertions. A grader evaluates them against the complete trace of what the caller and agent said and what the agent did, including tool invocations, arguments, and returned rows. This catches an agent that claims to have changed a card without updating the database, as well as one that makes the right database change while disclosing protected information. This first benchmark version focuses on financial services. Its evaluation protocol supports an evolving leaderboard: additional voice agents can be evaluated on the same version, while later versions can expand the tasks and scenarios.

## 2. 论文提出的方法论

- **核心思想**：构建一个**有状态、端到端、可重复**的语音智能体模拟基准，让被测智能体通过真实音频电话呼叫完成信用卡客服任务，并基于“对话+执行轨迹”联合判定成功与否。
- **基准设定**：
  - 智能体角色为“Riley”，虚构银行的信用卡支持代表，可执行冻结、取消、替换或激活卡片。
  - 提供**5个工具**，执行**真实SQL**操作PostgreSQL后端。
  - 策略包含：验证前置（先取得卡号后四位+姓名+地址/电话，验证通过后才可操作或披露信息）、替换前先冻结、标准配送时长为14个工作日、范围外请求转接指定号码。
- **模拟环境设计**：
  - 每个场景独立容器化模拟，各有独立种子数据库与呼叫者人格。
  - 模拟呼叫者持有**私有目标**，可跨轮次坚持请求、在被拒绝时要求升级，并自行决定结束通话。
  - 通过WebSocket传输24kHz PCM16原始音频，支持WebSocket/WebRTC/Twilio等传输适配器，工具调用支持进程内/WebSocket/HTTPS webhook多种方式。
- **评估机制**：
  - 每个场景定义**二元断言**（81个场景1条、17个2条、2个3条）。
  - LLM评分器基于**完整轨迹**（对话、工具调用、参数、返回行）逐断言判定PASS/FAIL，全部通过才算任务完成。
  - 联合评估可捕获：声称完成但未执行工具调用、执行了正确操作但泄露了受保护信息、前后操作顺序违规等仅靠单通道无法发现的问题。
- **场景分类**：100个场景划分为互斥的三组——简单流程（30个）、复杂流程（38个，含多次工具调用、中途数据库变化、多卡等）、对抗性与防护（32个，含验证施压、保密性、范围外请求、策略顺序、身份伪装等）。

## 6. 论文的主要结论与发现

- **总体性能**：完成率43.0%–71.0%，整体平均63.1%；连接率98.3%，说明失败主要发生在通话过程中的对话或执行环节。
- **复杂流程是最大短板**：所有11个代理在复杂组表现最弱（全体52.2%），简单组65.8%，对抗组73.4%，复杂组失败主要由多步骤动作序列导致。
- **说与做严重脱节**：评审1290条失败断言解释后发现**至少27起明确的说/做不匹配**，分布在11个代理中的10个；典型场景是宣称已取消或已更换卡片，而工具调用记录中并无对应操作。
- **对抗性防护的两个维度表现迥异**：
  - 直接绕过尝试处理较好（经理绕过、员工施压、语音提示注入均以90%+通过率通过）；
  - **保密性是系统性弱点**：重复验证失败场景仅33.3%通过、探询错误字段仅39.4%通过、探询姓名/地址仅33.3%通过——代理会在拒绝操作时向未验证呼叫者泄漏验证字段信息，这恰是攻击者真正想要的“神谕”。
- **策略顺序在压力下崩溃**：当呼叫者要求跳过冻结直接换卡时，完成率仅3.0%；当呼叫者不耐烦催促跳过时，完成率39.4%——策略中的动作顺序被流畅对话掩盖。
- **架构对比观察**：
  - Pipecat（71.0%）与LiveKit（70.3%）在共享模型栈下差0.7个百分点；
  - Vapi与二者共享Nova-3家族ASR，三者差距1.7个百分点；
  - 全NVIDIA Nemotron管线（43.0%）较Pipecat基线（71.0%）相差28个百分点，其中包含模型行为与托管服务可靠性两方面的差异（33通未连接电话是TTS启动失败所致）。

## 7. 优点

- **端到端真实模拟**：通过真实音频电话呼叫、真实SQL后端、隔离模拟环境评估完整系统，而不是只测组件或文本模拟，更贴近生产部署的“单位价值=解决的通话数”。
- **联合证据评分是核心亮点**：将对话、工具调用、参数、返回行按统一轨迹交由同一组断言评估，能够捕获“说了但没做”（虚假宣称）与“做了但泄露”（正确操作+违规披露）两类纯单通道评分无法发现的错误。
- **严格可控的对比设计**：Pipecat/LiveKit共享三模型栈、Vapi共享LLM/TTS与Nova-3家族ASR、Nemotron与Pipecat仅换模型栈，提供了多层次的受控比较，可区分框架、模型与平台差异。
- **工程完备性**：传输适配器（WebSocket/WebRTC/webhook/telephony）归一化传输差异而不改变任务语义，支持自托管和供应商托管代理在同一基准上运行。
- **严谨的统计表述**：明确区分描述性排序与统计结论，不夸大消歧能力，误差棒只代表固定场景集上的重复运行变异，给出诚实的不确定性描述。
- **无金标准的人类标注缺失被如实披露**：论文对评分器、模拟呼叫者、成本快照等局限保持透明。

## 8. 不足与局限

- **领域覆盖窄**：仅一个金融场景集（信用卡操作），不适用于跨域、跨语言、跨口音、跨语速的泛化结论；文中无法确定口音和说话风格的效果是否被隔离。
- **运行次数有限**：每代理仅3次运行，运行间方差可达最高17个百分点（Nemotron），不足以区分紧密相邻的产品差异。
- **评分器可靠性风险**：单LLM评分器、无人工标注金标准集用于校准；模拟呼叫者的真实性未有对照真实客户交互验证。
- **缺少最终数据库状态检查**：当前基于轨迹（工具调用记录）推断外部动作，未在通话后额外查询最终数据库状态以确认持久状态，论文承认这一点并提出后续改进方向。
- **产品成本估算不一致**：成本估算基于价格快照（2026年7月底），部分为时长×单价模型推算，自托管方案不含服务器开销，固定年费许可证未折算，各项口径不完全一致。
- **Turn-taking控制差异**：各提供商暴露的控制力度不同，相同的目标端点检测阈值映射到不同的供应商设置，会引入代理间的隐式差异。
- **发布者利益冲突**：所有作者隶属于开发并运营该模拟平台的Veris AI，虽披露了该关系，但平台自身的客观性和对外推广角色可能带来一定偏见风险。
