## 摘要
上下文定制对于生产级自动语音识别（ASR）系统至关重要，此类系统必须在严格的延迟约束下准确识别用户提供的短语。尽管许多上下文偏置方法提高了识别准确率，但它们往往无法满足现代生产级ASR系统的实际要求：流式推理、高效的批处理解码、用户特定的上下文列表以及低运行时开销。我们提出了TurboBias 2.0，这是一个面向生产的框架，用于在基于Transducer的ASR系统中实现高效的短语增强。该框架通过不区分大小写的增强图和每流批处理解码扩展了GPU加速的TurboBias，使得批处理中的每个话语都能使用独立的上下文偏置配置。这为多个并发用户实现了个性化上下文偏置，而无需共享或混合他们的上下文列表。所提出的框架支持离线和流式推理，并可结合贪心和束搜索解码使用。实验表明，TurboBias 2.0在保持低延迟和高吞吐量的同时，提高了上下文短语的识别能力。

## Abstract
Contextualization is essential for production automatic speech recognition (ASR) systems, where user-provided phrases must be recognized accurately under strict latency constraints. Although many context-biasing methods improve recognition accuracy, they often do not address the practical requirements of modern production ASR systems: streaming inference, efficient batched decoding, user-specific context lists, and low runtime overhead. We propose TurboBias 2.0, a production-oriented framework for efficient phrase boosting in Transducer-based ASR systems. The framework extends GPU-accelerated TurboBias with a case-insensitive boosting graph and per-stream batched decoding, allowing each utterance in a batch to use an independent context-biasing configuration. This enables personalized context biasing for multiple simultaneous users without sharing or mixing their context lists. The proposed framework supports both offline and streaming inference and can be used with greedy and beam-search decoding. Experiments show that TurboBias 2.0 improves contextual phrase recognition while preserving low latency and high throughput.

## 2. 方法论：核心思想与技术细节

### 2.1 总体框架
TurboBias 2.0 是在原版 TurboBias（GPU加速短语提升树，基于 NGPU-LM 数据结构）基础上的生产级扩展，包含三大核心创新：

### 2.2 创新一：大小写不敏感的GPU短语提升图
- **问题**：原版提升树是大小写敏感的，用户输入"hello"无法匹配模型输出的"Hello"或"HELLO"；简单扩展为多大小写变体会增大树规模且仍不覆盖混合大小写情况。
- **核心方案——变体BPE分词表示**：
  1. 对每个短语获取贪心 SentencePiece 分词结果
  2. 将每个BPE token 分解为规范字符级片段（character-level chain）
  3. 在每个字符位置添加对应的单字符 token 弧
  4. 对所有规范分解能覆盖连续片段的有效词汇 token 添加合并弧（merged arc）
  5. 大小写不敏感的规范化：所有token先转换为小写规范序列，再与短语路径匹配
- **结果**：生成的结构不再是简单树，而是有多个弧跳过不同数量字符位置并汇聚到同一状态的**有向无环图（DAG）**，但仍可用与 TurboBias 相同的 NGPU-LM 数据结构编译。
- **分数分配机制（势函数差分法）**：
  - 由于不同路径弧数量不同，不能简单给每条弧相同分数
  - 在每个状态上存储**累计分数势能**（cumulative score potential），弧的分数 = 目标状态势能 − 源状态势能
  - 以全小写贪心BPE分词作为评分主干，将第 k 个BPE token 的分数 \( w_k \) 分配到其 \( m_k \) 个内部字符状态上，公式为：
    
    \[
    \Delta_{k,i} = w_k \frac{\exp((i+1)\tau)}{\sum_{j=0}^{m_k-1} \exp((j+1)\tau)}, \quad i = 0, \ldots, m_k-1
    \]
    
  - 其中 \( \tau \) 控制分数在token末端的集中程度：τ=0 为均匀分配；τ 越大越接近原版 TurboBias 行为（完整BPE token匹配时才获得大部分分数）
  - 同一终点状态的所有大小写变体和合并替代路径获得相同总短语加分，与具体BPE分词方式无关

### 2.3 创新二：每流（Per-Stream）上下文偏置
- **问题**：生产场景中同一批（batch）可能包含来自不同用户的流，各自的上下文短语列表不同；全局共享树会导致干扰和错误接受。
- **核心方案——多模型合并存储**：
  - 将多个提升树的张量（弧标签、目标状态、弧权重、状态出弧范围、后缀链接等）拼接为**合并的多模型存储**
  - 每个模型ID记录其在合并张量中的状态/弧范围偏移量和提升权重
  - 批处理解码时，每个流携带一个"偏置模型ID"：
    - 非负ID → 选择该流对应短语列表
    - ID = −1 → 表示无偏置，按普通流解码
  - GPU kernel 首先读取当前流的模型ID和偏移量，再执行标准后缀链接遍历
- **生命周期管理**：
  - **添加模型**：将弧/状态张量追加到合并存储末尾并记录偏移
  - **移除模型**：将后续弧/状态区间左移填补空隙（GPU并行化高效执行）
  - **三级缓存策略**：
    1. **磁盘存储**：持久化预编译提升树（适合大型或重复列表）
    2. **CPU内存存储**：按需复制到GPU合并模型（动态每流更新，开销小）
    3. **解码器级注册**：识别会话前已知模型，完全消除解码循环中的更新开销
- **性能**：每流只比单树情况多读取一次模型ID和两个偏移量，几乎不引入额外解码开销；典型每流提升模型小于1MB。

### 2.4 创新三：流式束搜索（Streaming Beam Search）
- 基于 ASLD++ 的离线批处理束搜索算法（[21]）扩展：
  - 支持按块（chunk）处理编码器输出，实现流式解码
  - 关键难点：跨块边界维持束搜索状态
  - 解决方案：将完成块级假设以**扁平树结构存储**，包含累计分数和边界解码器状态
  - 这些存储状态作为锚点，用于后续块中继续扩展、合并和剪枝新假设
  - 保持 CUDA Graph 兼容和全GPU批处理运算，实现低延迟流式束搜索

### 3.2 评估模型
- **parakeet-tdt-0.6b-v2 (TDT-v2)**：600M参数，FastConformer编码器 + TDT解码器，强离线基线

### 3.3 对比方法
1. **无偏置基线**（无上下文的贪心/束搜索解码）
2. **CTC-Word Spotter（CTC-WS）**：TDT-v2 生成转录 + TDT-CTC（parakeet-tdt-ctc-110m）做关键词检测和文本校正
3. **原版 TurboBias**（大小写敏感，case-sensitive）
4. **TurboBias 2.0** 各变体（大小写不敏感 + 每流偏置 + 贪心/束搜索）

### 3.4 评估指标
- **WER**：整体识别词错误率

- **流式延迟**：最坏情况算法延迟 = 块大小 + 右上下文

## 6. 主要结论与发现

1. **TurboBias 2.0 在离线和流式场景均有效**：直接透导解码器级短语提升即可获得显著上下文识别增益，无需辅助CTC路径、事后校正或模型重训。

2. **Unified 模型表现最优**：
   - 离线：Earnings22 上达到 87.5 F-score / 12.6% WER，非常接近 Argmax CTC-WS 的 F-score（88.2），且 WER 更低
   - 流式（1.12s延迟）：F-score 从 62.2 提升至 81.7，WER 从 16.3% 降至 14.3%
   - 在医疗数据集上明显优于 Nemotron-streaming 模型（71.1 vs 68.2 F-score；14.0% vs 18.0% WER）

3. **大小写不敏感图优于大小写敏感的"目标大小写"变体**：
   - 贪心：75.4 vs 74.8 F-score；束搜索：81.4 vs 80.6 F-score
   - 关键价值：消除了对输入短语列表大小写格式的依赖，对全小写列表尤其重要

4. **每流偏置显著优于全局共享树**：
   - 每流全局 + 束搜索：87.5 F-score（vs 全局树的 81.4）
   - 避免跨流干扰和干扰项造成的错误接受

5. **束搜索带来大幅增益**：从贪心到束搜索，F-score 通常提升 6-10 个点。

6. **缓存策略可有效隐藏模型加载开销**：解码器级注册方案下，RTFx 与全局树基线几乎无差异（1717 vs 1726 贪心；988 vs 1005 束搜索）。

## 7. 方法亮点

- **实用性导向**：每个设计都针对生产真实痛点（大小写问题、多用户隔离、流式延迟），而非仅为学术基准优化。
- **免训练部署**：无需修改ASR模型或重训练，可直接应用于现有Transducer模型。
- **大小写不敏感的优雅设计**：通过变体BPE表示 + 势函数差分分配分数，解决了BPE分词器缺乏大小写变体token的根本问题，且保证不同分词路径获得相同总加分。
- **每流偏置的高效实现**：合并张量存储 + 模型ID索引，在GPU批次内实现了真正的个性化，且额外开销极小（仅读取两个偏移量）。
- **三级缓存策略**：从磁盘到CPU到解码器级注册，覆盖了不同模型生命周期需求，具有很高的工程参考价值。
- **开源**：在 NVIDIA NeMo 工具包中开放（PRs #15800, #15125, #15753）。
