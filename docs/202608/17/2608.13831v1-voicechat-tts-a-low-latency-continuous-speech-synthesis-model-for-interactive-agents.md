## 摘要
口语对话是人机交互的一种自然形式，然而大多数语音语言模型仍然局限于基于回合的操作，缺乏实时适应性，例如用户插话。最近的双工语音到语音和语音到文本模型通过替换多阶段流水线来降低延迟，但常常牺牲语音质量，因为准确的ASR、中断处理和高保真合成必须联合优化。我们提出了VoiceChat-TTS，一种面向交互代理的低延迟、连续且可流式传输的文本到语音模型。VoiceChat-TTS直接由LLM文本令牌流驱动，通过控制令牌支持显式中断，并在没有文本输入时产生静音。该模型实现了始终在线、响应迅速的语音生成，同时保持了模块化和高语音质量，并支持在不清除KV缓存的情况下进行语句中途中断。

## Abstract
Spoken dialogue is a natural form of human--computer interaction, yet most speech language models remain limited to turn-based operation and lack real-time adaptability, such as user barge-in. Recent duplex speech-to-speech and speech-to-text models reduce latency by replacing multi-stage pipelines, but often compromise speech quality because accurate ASR, interruption handling, and high-fidelity synthesis must be optimized jointly. We propose VoiceChat-TTS, a low-latency, continuous, and streamable text-to-speech model for interactive agents. VoiceChat-TTS is driven directly by LLM text-token streams, supports explicit interruption via control tokens, and produces silence when no textual input is available. The model enables always-on, responsive speech generation while preserving modularity and high speech quality, and it supports mid-utterance interruptions without resetting the KV cache.

## 一、论文的核心问题与整体含义

**研究动机与背景：**

- 口语对话是人机交互最自然的形式之一，然而现有的语音语言模型大多局限于**基于回合（turn-based）的操作**，缺乏实时适应性，例如无法支持用户中途插话（barge-in）。
- 近期出现的双工（duplex）语音到语音（S2S）和语音到文本（S2T）模型虽然通过替换传统多阶段流水线降低了延迟，但**往往以牺牲语音合成质量为代价**——因为准确的 ASR、鲁棒的中断处理与高保真语音合成需要在单一架构中联合优化，数据与建模挑战巨大。
- 传统流水线包含独立的 ASR、VAD 和 TTS 组件，模块化好但延迟高；端到端双工模型延迟低但质量下降、可调试性差。现有流式 TTS 系统（如 Audio Flamingo 3-Chat、VoXtream、SpeakStream、Qwen3-TTS）主要解决单次响应内的流式生成，**未原生建模全双工交互代理所需的持续在线行为**——即在对话时间轴上始终活跃、无文本输入时生成静音、并能迅速响应用户插话停止发声。

**核心意义：**

本文提出的 VoiceChat-TTS 填补了上述空白——它是一个**低延迟、连续、可流式**的 TTS 模型，直接由 LLM 文本令牌流驱动，通过控制令牌显式支持中断，在无文本输入时生成静音，实现始终在线、响应式的语音生成，同时兼顾模块化与高语音质量。

## 二、论文提出的方法论

**核心设计思路：**

VoiceChat-TTS 构建在 Audio Flamingo 3-Chat 流式语音解码器之上，针对全双工交互需求引入多项关键修改。整个系统由 LLM 文本令牌流直接驱动，而非等待完整文本生成完毕，从而支持增量式、低延迟的语音合成。

**关键技术细节：**

1. **音频编解码器（Audio Codec）**
   - 全因果卷积自编码器，将 22 kHz 波形压缩为 12.5 Hz 帧率、31 码本 RVQ（Residual Vector Quantization）令牌。
   - 每个音频令牌帧对应 80 ms 波形块，与现有双工 S2S 模型（如 Salm-Duplex、Moshi）的帧率兼容。
   - 流式推理时仅缓存卷积块在其感受野内的输入。

2. **文本分词器（Text Tokenizer）**
   - 使用 NVIDIA Nemotron Nano 2 子词分词器，并新增 **BOS（序列开始）令牌**与**中断令牌**。
   - 在 LibriTTS test-clean 上，文本令牌平均速率为 4.16 Hz，约每 3 个声学帧对应 1 个文本令牌。
   - 训练时文本流向右填充以匹配声学序列长度；BOS 标记助手回合开始，中断令牌指示模型停止说话并过渡到静音。
   - **单令牌延迟机制**：文本流领先音频流一个令牌，提供有限的语言前瞻，确保模型在生成对应语音前至少观察到两个子词令牌。

3. **字符感知子词编码器（Character-Aware Subword Encoder）**
   - 解决 LLM 分词器词汇与 TTS 训练语料之间的分布不匹配问题（许多 LLM 子词在 TTS 语料中罕见或缺失）。
   - 每个输入子词先转换为字符序列，经浅层 Transformer 编码器处理后做平均池化，得到对未见子词具有泛化能力的字符感知嵌入。
   - 为子词延续令牌增设专用嵌入，改善长词或碎片化词的增量生成发音准确性。

4. **混合高斯估计头（Mixture of Gaussian Head, MoGH）**
   - 替代 31 步自回归解码管线，通过迭代式去掩码生成 RVQ 令牌。
   - 每轮迭代用 MoG 估计预测掩码 RVQ 令牌的连续嵌入向量，再量化为离散令牌；4–8 轮迭代即可实现高保真声学重建。

5. **音频提示条件（Audio Prompt Conditioning）**
   - 与 Audio Flamingo 3-Chat 不设显式说话人参考不同，VoiceChat-TTS 使用 **3 秒参考音频提示**提供显式说话人线索。
   - 训练时提示区域音频令牌预置在声学序列开头且损失被掩码；推理时用同样长度的提示初始化声学上下文。

6. **边界嵌入与门控融合（Boundary Embeddings and Gated Fusion）**
   - 为 BOS 和中断令牌引入可学习的文本嵌入，提供显式的会话轮次边界信号。
   - 针对基础解码器中高幅度 RVQ 嵌入导致的混合精度溢出和激活不稳定问题，在文本嵌入与声学语音嵌入之间引入门控融合机制，保证数值稳定性。

**模型参数规模**：总计 977M 参数——包括 778M 参数的 Gemma 3 流式 TTS 模块和 199M 参数的编解码器模型。

## 六、论文的主要结论与发现

1. **质量显著优于架构基线**：相比 Audio Flamingo 3-Chat，VoiceChat-TTS 在单轮设置中将 WER 从 4.51% 降至 2.00%，Squim-MOS 从 3.60 提升至 4.38，说话人相似性相当。相比 PersonaPlex（相同文本内容），CER 从 4.06% 降至 2.05%，WER 从 5.00% 降至 2.42%。

2. **达到与强基线相当的水平**：VoiceChat-TTS 的 Squim-MOS（约 4.38）接近 Qwen3-TTS（4.45）和 Chatterbox（4.27），虽在单轮可懂度和说话人相似性上仍略逊于面向单轮优化的系统，但额外提供了持续双工交互能力。

3. **多轮生成稳定**：1–4 回合内 WER 仅从 2.00% 小幅波动至 2.20%，Squim-MOS 稳定在约 4.38；未见说话人场景下 SECS 随回合数下降（0.757→0.685），表明长上下文说话人一致性在零样本场景仍是挑战。

4. **中断处理可靠**：模型学会了对中断令牌的强响应，IOR@320ms 达 96.8%；启用确定性静音强制后 IOR 达 100%，平均停止延迟从 228.3 ms 降至 89.9 ms，1 秒内语音泄漏从 169.1 ms 降至 55.8 ms，后续回合 AI-CER 仅 0.095%，且无需重置 KV 缓存即可恢复生成。

5. **延迟优势显著**：在 RTX A6000 上，VoiceChat-TTS 的总下一帧延迟为 9.62 ms（并发 1），较 Qwen3-TTS-12Hz 的 20.34 ms 提速 **2.1 倍**，且模型更小（977M vs 1.7B），为服务端开销预留了更大余量。

6. **实际部署验证**：VoiceChat-TTS 已作为 NVIDIA Nemotron VoiceChat-11B 双工 S2S 模型的开源语音解码器投入使用，证明了模块化解码器可集成到完整交互系统。

## 七、优点

1. **模块化与性能兼顾**：在保持传统流水线可调试性和模块化优势的同时，实现端到端双工模型的低延迟体验，是对两种范式的一个良好折中。
2. **创新技术组合**：字符感知子词编码器解决 LLM 词汇与 TTS 语料不匹配问题；MoGH 加速深层 RVQ 生成；门控融合提升训练稳定性——各项设计针对性强、彼此互补。
3. **训练策略巧妙**：通过单轮数据前置静音增强，弥合单轮 TTS 与多轮双工场景的分布差距；合成 + 真实对话数据混合，兼顾可控性与自然度；统一处理单轮与多轮样本，杜绝模态差异。
4. **面向实际部署的工程优化**：编解码器流式缓存、31 码本查找融合为单一 CUDA 核、FP32 原生核替换、逆 STFT 常数缓存等，保证低延迟实时推理。
5. **中断机制设计简洁有效**：基于控制令牌的中断 + 确定性静音强制策略，既保留模型学习能力又提供严格合规选项。

1. **缺乏用户音频条件**：模型无法感知用户语音的声学特征，因此在韵律上不能动态适应用户的声学线索（如情绪、语速），限制了交互的自然度和表现力。

2. **无组件级消融实验**：论文未系统量化各架构改进（字符感知编码器、门控融合、音频提示等）的独立贡献，尽管作者表示开发中初步实验显示各组件增益是累积的，但缺乏严谨的对照证据。

## 八、不足与局限（续）

7. **端到端系统层面的评估缺失**：论文的重点是针对 VoiceChat-TTS 作为语音解码器模块的性能验证，但在实际双工对话系统中，TTS 模块接收的是由 ASR、对话策略和 LLM 共同产生并可能包含错误的文本流。论文的实验大多基于“理想的”文本流（如固定 PersonaPlex 预测的文本、脚本转写文本），并未模拟由 ASR 噪声、语义歧义或策略切换造成的文本流不稳定情况。因此，**模型在真实全双工管线中的鲁棒性尚未得到充分检验**，文本输入的质量对最终语音输出质量的影响程度也未被量化。

8. **跨语言与多语种支持未涉及**：全部训练语料均为英文（LibriTTS、HiFiTTS、Fisher 及内部英文数据），模型在评估中也只在英文上验证。作者未讨论模型对其他语言的泛化能力，例如字符感知子词编码器对非拉丁字母语言（如中文、日文）的效果尚未说明，限制了其作为通用双工语音交互组件的话语权。

## 九、总体总结

VoiceChat-TTS 是首个专为**连续、全双工交互场景**设计的低延迟流式 TTS 系统，其核心创新在于将 LLM 文本令牌流作为语音生成的连续驱动源，引入控制令牌显式处理中断与静音，将传统 TTS 的“回合式生成”范式升级为“持续在线生成”范式。

该论文的价值不仅在于提出了一种具体的模型，更在于为双工语音交互提供了一种**模块化、高性能、可工程落地**的解决方案——它既避免了端到端 S2S 模型难以调试、质量不稳的问题，又突破了流式 TTS 只能处理单次响应、无法响应中断的局限。实验表明，模型在语音质量、说话人相似性、多轮稳定性及中断响应速度上均达到了或超过了同量级强基线水平，并已在 NVIDIA Nemotron VoiceChat-11B 中实际部署，证明了这一技术路线的可行性。

当然，作为新兴方向的早期工作，它在用户音频感知、组件消融、长上下文说话人一致性及跨语言泛化等方面仍留有较大改进空间。但整体而言，该论文为“始终在线、自适应的语音合成”奠定了坚实的方法论基础，对后续研究具有重要的参考意义。
