## 摘要
用于内容创作的语音编辑需要精确控制编辑的操作内容及其应用位置。自由形式的自然语言为表达编辑请求提供了灵活的接口，但其模糊性可能导致预期的操作、参数或目标区域未被充分指定。我们研究了一种精确且显式的语音编辑接口：一种基于转录文本的结构化编辑指令，使用XML风格的标签显式指定类型化操作，并将其定位到转录文本的片段或边界。这种语义时间线避免了显式的时间戳对齐，并为组合编辑提供了外部可检查的契约。我们在dots.tts.edit中实例化了该接口，这是一个从连续自回归dots.tts基础模型改编而来的编辑器。四种代表性的语音创作控制涵盖了词汇内容、情感表达、音高和语速传递，以及通过文本、情感、韵律和停顿编辑实现的节奏断句。特定任务的数据管道构建操作和范围受控的配对，同时保留每个目标区域之外的源派生上下文。我们进一步引入了doteBench，一个双语评估套件，用于衡量四种控制及其组合的精确指令遵循、局部保留和音频质量。实验表明，在其五个编辑类别中，整体指令遵循和局部保留均处于领先地位，而音频质量与现有的开源系统相当。在三个Seed-TTS-Eval分片中，该模型在零样本TTS识别错误率和说话人相似性方面与基础模型的差异可忽略不计。代码和模型将很快发布。

## Abstract
Speech editing for content creation requires precise control over both what an edit should do and where it should apply. Free-form natural language provides a flexible interface for expressing edit requests, but its ambiguity may leave the intended operation, parameters, or target region underspecified. We study a precise and explicit interface for speech editing: a transcript-grounded structural edit instruction with XML-style tags explicitly specifies typed operations and localizes them to transcript spans or boundaries. This semantic timeline avoids explicit timestamp alignment and provides an externally inspectable contract for compositional edits. We instantiate the interface in dots.tts.edit, an editor adapted from the continuous autoregressive dots.tts foundation model. Four representative speech-creation controls cover lexical content, affective expression, pitch and speaking-rate delivery, and temporal phrasing through text, emotion, prosody, and pause editing. Task-specific data pipelines construct operation- and scope-controlled pairs while retaining source-derived context outside each target region. We further introduce doteBench, a bilingual evaluation suite that measures precise instruction following, local preservation, and audio quality across the four controls and their composition. Experiments show leading overall instruction following and local preservation across its five editing categories, while audio quality remains comparable to existing open-source systems. Across three Seed-TTS-Eval shards, the model shows negligible differences from the base model in zero-shot TTS recognition error rate and speaker similarity. The code and model will be released soon.

  - 多数系统依赖显式的强制对齐器将文本跨度映射到音频时间戳，增加了复杂性且对齐结果不稳定。
- **本文的解决思路**：提出一种**基于转录文本的XML式结构化编辑指令**，通过显式标签指定操作类型、参数，并将操作局部化到转录文本的跨度（span）或边界（boundary），形成一套**外部可检查、可组合、无需显式时间戳对齐**的“语义时间线”编辑契约。
- **整体意义**：为语音编辑提供了一种精确、显式、可组合的编辑控制接口，既适用于人工工作室编辑场景，也适合作为智能体音频创作工作流中的可调用工具。

## 2. 论文提出的方法论

### 2.1 核心思想：转录级结构化编辑指令

- 编辑样本定义为五元组：`d_edit = (T_src, A_src, u, T_tgt, A_tgt)`
  - `T_src` / `T_tgt`：源/目标转录文本
  - `A_src` / `A_tgt`：源/目标波形
  - `u`：转录级结构化编辑指令（XML风格标签）
- 指令中的标签类型：
  - **跨度操作（Span）**：包裹转录 token，如 `<sub targ="concert">meeting</sub>`
  - **点操作（Point）**：标记词边界，如 `<pause act="ins" level="2"/>`
- 两类确定性渲染器：`g_src(u)` 去除标签保留源侧词汇；`g_tgt(u)` 应用词汇插入、删除、替换。

### 2.2 四类代表性编辑控制

| 编辑类别 | 操作内容 | 局部化方式 |
|---------|---------|-----------|
| 文本编辑 | 词汇插入、删除、替换 | 转录跨度或边界 |
| 情感编辑 | 全局或局部情感表达改变 | 跨度或全局 |
| 韵律编辑 | 音高（pitch）或语速（speaking rate）调整 | 跨度 |
| 停顿编辑 | 在词边界插入、延长或缩短停顿 | 边界 |

### 2.3 数据构造管道

- **共享原则**：每条管道构建“来源可追溯的原始/生成配对数据”，显式记录操作类别、参数和定位信息。
- **双向序列化**：每对构造数据同时提供原始→生成和生成→原始两个方向的监督（即一次干预产生两个训练样本）。
- **各任务管道**：
  - **文本编辑**：强制对齐定位源跨度，用F5-TTS在被掩码区域进行局部填充重建。
  - **情感编辑**：基于IndexTTS2在固定说话人条件下对不同情感条件渲染同一文本，通过拼接实现局部情感替换。
  - **韵律编辑**：PSOLA实现音高变换、WSOLA实现时间拉伸，再用IndexTTS2 tokenizer/decoder重建恢复自然度和说话人音色。
  - **停顿编辑**：插入精确的200/500/800ms静音，用F5-TTS重建停顿及其两侧短窗口以保持过渡自然。
- **边界修复**：对拼接处的窄邻域用F5-TTS的掩码重建能力进行重合成，消除可听见的接缝。

### 2.4 模型架构与训练

- **基础模型**：dots.tts，一个2B参数的连续自回归TTS基础模型。
  - 48kHz AudioVAE（基于HoliTok），产生25Hz潜变量流
  - 每4帧压缩为6.25Hz语义表示，自回归预测后用流匹配头生成连续潜变量
  - 冻结的CAM++说话人编码器提供全局身份条件
- **编辑条件序列**：`[T_src, Z_src, u, T_tgt, Z_tgt]`
  - TTS与编辑共用同一条件生成器，但编辑额外观察源转录、源语音、指令和目标转录
- **训练目标**：
  - 流匹配损失（flow matching）：预测目标速度场 v_θ(x_t, t; c)
  - 掩码下一token交叉熵损失：L_CE
  - 音频结束预测损失：L_EOS
  - 总损失：`L = λ_FM·E[||v_θ(x_t,t;c) − v★||²] + λ_CE·L_CE + λ_EOS·L_EOS`（三个权重均为1）
- **训练混合比例**：TTS:文本:情感:韵律:停顿 = 48:4:4:2:1
- **数据增强**：60%编辑样本拼接2-3段独立片段（最长40s）创建多说话人上下文；10-20dB SNR噪声增强。

## 7. 优点

- **接口设计的创新性**：转录级XML风格结构化指令是语音编辑接口的一个新颖设计，兼具表达力与可检查性：
  - 操作类型和参数显式化，用户无需从模糊文本推断意图
  - 通过语义时间线（而非时间戳）定位，更贴近人类交互习惯
  - 多操作可序列化为一个组合编辑程序
- **数据构造的工程智慧**：
  - 各任务管道以“一次干预”为核心创造来源可追溯的配对数据
  - 双向序列化（原→生成、生成→原）使数据利用效率翻倍
  - 记录音频作为目标侧可防止目标监督完全依赖合成音频
  - 边界F5-TTS修复巧妙平衡了自然过渡与局部保留
- **模型设计的简洁性**：无需新增任务特定的修补网络，仅通过改变条件序列和配对训练数据即可实现编辑能力，保留了基础TTS的能力。
- **评估体系的可解释性**：doteBench将指令遵循、局部保留、音频质量三个维度解耦，每类指标都针对具体编辑类别设计，可解释性强于LLM-judge类指标。
- **证据充分性**：大量实验表格覆盖各类别、各系统的完整对比，验证体系全面且规范。

### 应用限制

- **不支持说话人转换**：模型可以保留多说话人的身份，但不能转换说话人；doteBench也未覆盖多说话人编辑任务。
- **未评估智能体集成**：论文未在端到端智能体工作流中实际测试该编辑器。
- **未进行自然语言接口的直接对比**：论文未提供自然语言接口与结构化指令接口的匹配对比，精度声明仅限于控制契约的显式性和可检查性，而非确定性生成或因果优越性。

### 实验覆盖的局限

- **音频质量仍有提升空间**：虽然UTMOS优于管道基线，但整体音频质量距离“完美自然”尚有距离。
- **组合编辑场景表现不足**：情感组件成功率仅18.84%，韵律和停顿在组合场景中也大幅下降——多操作并行执行时的干扰问题未完全解决（基础模型本身的能力限制）。
- **评估依赖外部评判器**：情感准确率依赖Gemini的感知判断，其偏差会影响结果的可复现性。

### 偏差风险
